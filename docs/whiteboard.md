# Whiteboard

Open **Whiteboard** from a live Pi chat. Fernblick loads the Excalidraw editor only when needed. Back returns to the same chat without clearing its composer. The native scene and raster assets are saved separately from chat uploads, one board per Herdr socket / Pi conversation. Forks get separate boards; restarting or reloading Pi does not grant access again.

## Staying in the conversation

The whiteboard uses the same chat transcript as main chat: all available messages, the same message bubbles, images and image previews, tool results, status messages and thinking preference. There is no latest-reply-only filter. Both views still use the existing bounded recent transcript; a truncation notice appears when older content is omitted by the live-chat feed.

On landscape screens at least 1024 CSS pixels wide, the canvas and chat sit side by side (roughly two-thirds / one-third). Expand widens chat to half the workspace. On portrait and narrower screens, chat stays in a compact bottom panel; scroll normally to earlier messages. Expand uses the workspace for chat, keeping the drawing mounted but hidden until Collapse. Rotation and expansion change the layout, not the message set or draft. Streaming follows only while you are near the bottom; resizing preserves your reading position.

Saved snapshots are in a separate collapsible section, available in the landscape side panel or expanded portrait view. Working, reply and permission status share one row, including Stop editing when applicable. Attachment previews can be closed with Escape without dismissing the whiteboard.

The dock shares the ordinary chat text draft. **Send** (or Cmd/Ctrl+Enter) submits your instruction into the same Pi conversation with read/edit access to this board for that request. Just type what you want drawn or changed; no Share step or permission picker is needed. The mode displays this editing authority above the prompt. Current native changes are saved before sending. For a nonempty board, Send automatically exports and attaches a current PNG so the agent can interpret handwriting, sketches and embedded images alongside its structured editing tools. Empty boards skip the image. Queued chat images are never attached; they remain in the chat composer. Enter inserts a newline. Failed or uncertain sends keep the draft and do not retry automatically. Back returns to chat with unsent text intact; normal chat outside whiteboard mode does not grant board access. Ordinary chat text remains an in-memory draft rather than a reload-proof backup.

## Sending and permission

**Share drawing** opens an image-only PNG preview, with an optional accompanying message. It sends a snapshot without live board tools. The uploaded PNG and native scene are retained as an immutable revision even if later delivery fails; snapshot history does not prove Pi accepted a message.

Automatic prompt images use ordinary chat uploads and do **not** create Saved snapshots. Saved snapshots are created only by Share drawing. PNGs are captured on Send, not continuously; the canvas is briefly locked during preparation. If export/upload fails or the board/agent changes during preparation, sending stops with the draft retained rather than silently losing visual context.

Whiteboard mode authorizes each dock prompt to read/edit this conversation's board. Opening or drawing alone does not invoke the agent or expose tools indefinitely. Each prompt gets a fresh request-scoped grant; Stop editing revokes the current grant, and a later dock prompt starts a new authorized request. Image sharing and ordinary chat do not carry a grant.

A whiteboard-mode prompt enables `board_read` and `board_apply`. The extension registers both tools hidden/inactive by default, then activates them only after the matching extension-origin input and prompt have been observed and the backend has authorized the request. Unrelated tools are preserved. User prompt text is forwarded unchanged: the extension adds one authorized-turn system instruction while preserving base/other extension instructions, rather than appending boilerplate or a duplicate access notice to chat. When an image is attached, this instruction identifies it as the board at send time and guides handwriting/sketch interpretation; tools still read current state and enforce revisions. This guidance is not authorization and is not added to later ordinary turns. Activation failures retain their informational notice. Tokens are never included in model input or tool results. The private socket carries separately correlated board RPCs, not chat commands.

Grants are tied to a board, runtime, epoch, and Pi session. They end on settlement, explicit revocation, stop, new input, session changes, connection replacement/disconnect, or expiry. Pending backend grants last at most 30 seconds; active grants at most 15 minutes. The extension also has a 15-second handoff guard and five-second RPC timeout. Failed or timed-out mutations are not automatically replayed. Backend authorization is checked again at the durable commit point, not just when a request arrives.

Permission controls govern **this board integration**, not Pi's existing shell/filesystem access. Revoking permission does not erase an image or text already sent to the conversation. As with the rest of Fernblick, access to the web app is trusted controller access: keep it restricted to the intended Tailnet users, not the public internet.

## Editing, conflicts, and recovery

The browser autosaves with compare-and-swap revisions and three-way reconciliation: the acknowledged base scene, current unsaved drawing, and latest server scene. Independent additions/changes from both sides survive either save order. Competing edits keep the local human record; new deletions win over concurrent edits, without treating unseen incoming additions as local deletions. Native order, tombstones and referenced image files are retained. Remote updates wait until the active stroke/text/multipoint gesture ends. Editor restoration-only fields are not mistaken for human changes. Incompatible native bindings/frames, fresh ID collisions, conflicting image assets or merged size limits still pause for explicit recovery rather than producing a broken board.

Only a `board_stale` HTTP 409, emitted before any server write, allows bounded refetch/reconciliation (up to three per flush). Generic failures, timeouts, disconnects and invalid ACKs never trigger automatic write retries. The draft stores its actual base scene and a paused marker before a write, so a crash/reload cannot replay an in-flight or uncertain save. New strokes arriving during reads/writes are carried forward. IndexedDB remains best-effort: unavailable/quota-failed storage is visible and is not a backup. Explicit Load latest first stores a recovery copy, refuses replacement if the human draws during its fetch, and keeps a Download previous local drawing action after replacement. Legacy dirty drafts without a trustworthy base stay paused.

Agent operations are checked against the latest scene inside the serialized commit lane. New standalone shapes tolerate unrelated drawing. Every update/delete target and explicitly declared `dependsOn` shape must have been returned by `board_read` at the submitted base revision and still match its complete native record. The model must declare dependencies for coordinate-only additions that rely on an existing shape. Read fingerprints are grant-local and bounded to live shape IDs. Changed/deleted/unread targets or dependencies skip their operation; shared `groupId` operations stay together. Independent eligible operations commit once, and the result lists `applied` IDs and `skipped` IDs/reasons. Deleting an already missing/deleted target reports `already_deleted` without a write. The agent is instructed to reread/reconsider skipped work and explain omissions, never replay applied operations. Invalid/unsupported operations still reject before committing any eligible edits; duplicate/tombstoned IDs and future revisions remain rejected. All-skipped outcomes are recorded for idempotency without incrementing the board revision.

Agent operations are deliberately narrow: create standalone rectangles, text, and arrows; move/recolor/resize supported unbound shapes; or delete them. Bound, grouped, locked, framed, or unsupported shapes cannot be edited through these tools. Read results are bounded, paginated summaries, without embedded files or full freehand paths. The attached PNG provides that visual context at send time; handwriting interpretation depends on the selected model's vision support and legibility. Tools do not provide a fresh rendered image after every edit. Agent editing is not a complete headless Excalidraw layout/rendering engine; complex diagrams should be reviewed in the editor. There is no live human multiplayer protocol, per-stroke model invocation, or separate AI service.

The backend owns durable state, so an authorized agent can finish edits while the browser is asleep or closed. The browser receives SSE invalidations and reloads the current scene on reconnection. Incoming edits are merged with unsaved browser drawing; unsupported relationship/asset conflicts retain explicit recovery. This is deterministic record-level reconciliation, not CRDT synchronization or collaborative undo. Applying a reconciled remote scene clears native undo history so Undo cannot silently remove agent work.

## Storage and limits

- `FERNBLICK_BOARD_DIR`: defaults to `~/.local/share/fernblick/boards`; use a distinct directory per development backend.
- The directory must be owned, non-symlinked, and `0700`; files are private and atomically replaced. Grants are memory-only and do not survive backend restart.
- A native scene is limited to 12 MiB. PNG uploads retain the existing 10 MiB image limit. Board schemas additionally bound elements, files, text, operation batches, and coordinates.
- Up to 128 immutable captures per board and 128 recorded operation-batch outcomes per grant. Limits fail explicitly rather than silently deleting sent revisions or replay protection.
- Snapshot PNGs and downloadable `.excalidraw` scenes are served under `/api/boards/:boardId/snapshots/:snapshotId.png|json`. They are not temporary uploads. There is no automatic board/snapshot retention cleanup in this release; back up/manage the private directory as appropriate.

The editor and fonts are served locally. Excalidraw always appends a CDN font fallback even with its asset path configured; `tools/local-excalidraw-fonts.ts` rewrites that pinned declaration to same-origin in development and production, with fixture tests against both vendor bundles. This avoids fallback requests/CSP violations without relaxing network policy. `npm run prepare:whiteboard` copies fonts from the pinned Excalidraw package into ignored `public/excalidraw/fonts/`; dev-web/build hooks run it automatically. License notices are shipped in `public/licenses/excalidraw/`. Excalidraw's vendor stylesheet is imported with the lazy editor; Fernblick-owned styling uses CSS Modules. Production CSP permits the inline styles/data fonts/blob workers required by the editor, but not remote scripts or network services.

See [development isolation](development.md) for separate ports, proxies, Pi extensions, and Herdr sessions. Existing Pi agents need `/reload` (or a restart) to load this extension version before board tools become available. Image-only sending remains separate from tool capability detection.
